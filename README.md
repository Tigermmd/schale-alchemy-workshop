# Schale 养成规划工作台

给《蔚蓝档案》玩家使用的国服礼物养成规划工具。

它可以帮你回答这些问题：

- 手上的礼物，应该先给哪位学生？
- 在指定天数内，距离目标好感还差多少？
- 按当前库存和免费资源，大约还需要多少天？
- 制造的三个阶段应该选哪些节点，平均能获得多少好感？
- 活动、总力战、大决战、制约解除作战和日程资源，应该怎样计入规划？
- 某个礼包对目标学生到底能提供多少好感，每 1 元值不值得？

项目面向中国服玩家，页面支持中文、English、日本語。它是玩家制作的非官方工具，与 NEXON、《蔚蓝档案》运营方、SchaleDB 或 arona.icu 没有隶属关系。

## 你能用它做什么

### 养成规划

添加一位或多位学生，设置当前好感、目标好感和规划天数。页面首屏直接显示：

- 目标好感缺口；
- 当前库存能提供的好感；
- 规划周期内的免费资源好感；
- 按平均日收益估算的达成天数。

礼包不会偷偷混入免费规划结果。未按国服进度实装的学生，也不会被计算日程和咖啡厅摸头，只按礼物规划。

### 库存管理

库存页可以记录 52 种具体礼物、制造启动石、金色合成石、礼物盒和活动商店的等效随机礼物池。

- 当前持有库存、周期资源和规划预留分开显示；
- 规划先生成预留，确认消耗后才扣除具体礼物；
- 支持兼容 arona.icu 的库存 JSON 导入和导出；
- 金色礼物自选盒和紫色礼物随机盒分开计算，不会混成一种盒子；
- 随机盒只计算期望好感，不会伪装成某件具体礼物。

### 周期资源

可以填写或修改每周、每月、每天获得的资源，包括制造启动石、金色合成石、活动商店礼物、总力战、大决战、制约解除作战、日程和咖啡厅摸头。

制约解除作战支持选择预设层数，也支持输入自己的实际通关层数。页面会根据当前层数汇总礼物盒和合成石奖励。

### 礼包性价比

礼包独立于养成规划，用目标学生的礼物反应计算：

- 预计获得的好感；
- 礼物、花束、金色盒、紫色盒和制造资源的分项贡献；
- 每元能获得多少好感。

它只提供消费参考，不会自动修改库存、购买记录或免费资源规划。

### 学生与礼物图鉴

查看学生喜欢哪些礼物、游戏内不同好感反应对应的礼物价值，以及完整三阶段制造节点的期望。制造节点最多展示五个候选，并把不是礼物的产出按 0 好感处理。

### Agent 助手（可选）

如果你有自己的 OpenAI 兼容接口，可以填写 Base URL、API Key 和模型，让本机 Agent 根据当前规划生成自然语言建议。

Agent 只能提出规划变更，所有变更都必须由玩家确认后才会应用；它不能直接改库存、消耗礼物或执行网页代码。API Key 只保存在本机代理进程内存中，不写入浏览器本地存储、导出文件、URL 或日志。

## 开始使用

运行环境：Python 3.10 或更高版本。页面不需要安装 npm 依赖。

```bash
git clone https://github.com/Tigermmd/schale-relationship-dashboard.git
cd schale-relationship-dashboard
python3 harness_server.py
```

然后打开：<http://127.0.0.1:8765/>

不熟悉 Git 的话，也可以在 GitHub 页面点击 **Code → Download ZIP**，解压后在项目文件夹中运行同样的命令。

如果只想查看规划页面，不使用 Agent，也可以运行简单的静态服务器：

```bash
python3 -m http.server 8765
```

这种方式不提供 Agent API。使用 `harness_server.py` 时，页面和本机 API 由同一个服务提供：

- 页面：<http://127.0.0.1:8765/index.html?view=planner>
- 健康检查：<http://127.0.0.1:8765/api/health>

自定义端口：

```bash
SCHALE_HARNESS_PORT=8766 python3 harness_server.py
```

## 计算口径

### 制造

- 一枚制造启动石等于 10 个制造石碎片；
- 启动石只计入第一阶段，第二、第三阶段使用的其他游戏内材料不计入启动石消耗；
- 每个阶段按照游戏机制生成五个候选节点，再从当次候选中选择目标学生期望最高的节点；
- 产物不是礼物时直接按 0 好感处理；
- 三个阶段的期望好感相加，得到一枚启动石对应的完整制造期望。

### 礼物盒

项目严格区分以下物品：

- `100008`：金色礼物自选盒，只能选择可制造的金色礼物；
- `100009`：紫色礼物随机盒，在可制造的紫色礼物池中等概率随机；
- 不存在“紫色礼物自选盒”这一默认物品。

活动商店中种类不固定的金色礼物，会作为“等效随机金礼物池”参与期望计算，但不会显示成实际持有的礼物盒，也不会拆成虚假的具体礼物库存。

### 国服进度

学生上线状态使用跨服务器一致的学生 ID，并按国服截止进度判断：

- 已实装学生：可以计入日程和咖啡厅摸头；
- 未实装或无法确认的学生：只按礼物计算；
- 日程和咖啡厅的共享资源只分配给当前主目标，避免多位学生重复获得同一份资源。

## 数据和图片来源

本项目的学生、礼物、好感阈值、制造数据和部分中文名称以 [SchaleDB](https://schaledb.com/) 的数据为基础；学生目录保留当前快照中的完整 272 名学生，其中 212 名标记为国服已实装，未实装学生仍可用于礼物规划，但不会自动计入日程和咖啡厅摸头。页面中的学生头像、礼物图标、反应脸和部分 UI 图片也来自 SchaleDB 的公开资源，并在本地缓存后随页面展示。具体抓取时间、版本和来源 URL 保存在 `relationship_data/*.json` 的 `source` 字段以及 `assets/manifest.json` 中。

项目参考了 [arona.icu](https://arona.icu/) 的库存 JSON 导入/导出、养成规划和资源管理体验，并据此设计了兼容导入和本地库存工作流。这里是功能与交互层面的参考，不代表双方存在合作、授权或从属关系。

数据中还包含国服公告、中文社区资料和玩家确认的计算口径。官方未公开或无法稳定核验的数值会标明来源和边界；玩家确认值可以在页面中修改，不能把它们理解为官方声明。

更详细的数据字段和制造机制说明见 [`relationship_data/README.md`](relationship_data/README.md)。

## 本地数据与隐私

库存、规划、语言和部分页面设置保存在浏览器本地。仓库不提供账号系统，也不会上传个人库存。

使用 Agent 时，API Key 只进入本机 Harness 进程内存。提交或分享项目之前，请确认没有把以下内容加入仓库：

- `.env`、私钥或其他凭据；
- 个人库存 JSON；
- 浏览器导出的本地状态；
- 含有 API Key 的日志或截图。
