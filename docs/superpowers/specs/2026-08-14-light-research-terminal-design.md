# 轻量研究终端：养成规划工作台设计

状态：视觉方向 A 已由用户确认，等待实施前复核

## 1. 目标

把现有礼物养成 dashboard 重构为一个“轻量研究终端”：用户打开后先看到当前目标和可执行结论，库存、制造节点、资源来源和 Agent 等复杂信息按需展开。页面保留 Blue Archive 的蓝白游戏感和真实学生/礼物素材，但不再使用蓝图网格、重复英文眉题、密集边框和长篇解释作为主要视觉语言。

首屏只回答：

- 当前规划目标是谁、目标等级是什么；
- 指定周期内还差多少好感；
- 按免费资源预计还要多少天；
- 下一步能做什么。

礼包价格和购买建议只存在于“礼包性价比”，不进入养成规划结果。

## 2. 信息架构

全站使用左侧窄导航轨道（桌面）和顶部/抽屉导航（窄屏），工作区固定为：

1. 养成规划：主工作区，默认入口；
2. 库存：当前持有、周期计入、预留、剩余；
3. 周期资源：免费资源输入和预测；
4. 礼包性价比：独立消费参考；
5. 学生与礼物图鉴：角色、喜欢礼物和制造路径；
6. Agent 助手：自然语言辅助，不直接改状态。

公共壳层只保留品牌、当前工作区、语言切换和数据快照状态。品牌级装饰只出现一次，页面不再同时展示重复的“工作台/ledger/index/CN”眉题。

## 3. 规划页（主路径）

页面从上到下分为三层：

### 3.1 目标栏

- 主目标学生头像、中文名、英文/日文按语言切换显示；
- 当前等级、级内好感、目标等级；
- 规划周期输入；
- “修改目标”“添加学生”两个操作；
- 未实装学生显示一个短提示：只按礼物计算，不计入日程和咖啡厅。

学生选择使用全量数据搜索，不显示内部 ID；搜索无结果时清空详情，不保留上一位学生的误导性内容。

### 3.2 结果卡

每个规划学生卡片的首屏 KPI 固定为：

- 好感缺口：指定周期内仍缺少的好感值；
- 预计达成：按免费资源日均收益估算的天数，无法估算时显示“无法估算”；
- 当前库存贡献、周期免费贡献：作为次级指标。

主目标独占日程、咖啡厅和共享周期资源；其他学生明确提示需要切换主目标后才能计入共享资源。所有好感、概率和期望值保留两位小数；数量、等级、层数、购买次数等整数按整数显示。

### 3.3 可折叠明细

默认折叠“礼物分配”“资源来源”“计算口径”。展开后才展示具体礼物图标、反应脸、三阶段节点、随机盒期望和预留操作。

“生成预留方案”固定放在结果卡的操作区，不藏在长礼物列表底部；确认消耗仍是二次确认，随机盒和等效随机池不参与具体礼物精确扣除。

## 4. 其他工作区

### 库存

默认突出可编辑的“当前持有”。周期计入、预留和规划后剩余放在行内详情中。具体礼物以图标 + 名称 + 好感值筛选，52 种数据在 0 库存时仍显示明确空状态和“显示全部”入口。礼物盒独立显示：100008 是金色自选盒，100009 是紫色随机盒，不转换成具体礼物。

### 周期资源

首屏显示规划周期、已配置/待填写数量和有效好感；待填写项直接显示在摘要下方。来源、证据、调研线索进入折叠区，不在默认列表中铺开。

### 礼包性价比

默认显示主目标的前三个礼包，按好感/元降序；完整列表、购买上限、来源和快照时间放入“查看全部”。金礼物、紫礼物、花束、金色自选盒、紫色随机盒、制造石分开列出期望好感，绝不出现紫色自选盒。该页只读展示，不修改购买计划。

### 学生与礼物图鉴

桌面为“可收起学生目录 + 角色详情”；窄屏目录默认收起，搜索/选择后自动定位详情。详情优先显示角色头像、加成礼物：按数据中的三档游戏内反应脸分成三行，不在界面硬编码错误的礼物分值；礼物筛选页仍提供 240/180/120/80/60/40/20 全部分值。三阶段制造结果默认只给期望摘要，节点概率、候选礼物和非礼物产出进入展开区。

### Agent

首屏是对话与当前规划摘要；连接配置放入设置抽屉。未连接时发送入口明确禁用，并显示“配置 → 测试 → 提问”的短流程。Agent 上下文可读取规划结果、库存摘要、周期资源和礼包性价比，但建议必须经用户逐项或全部确认后由本地纯函数应用；禁止修改库存、执行代码或写任意 localStorage。

## 5. 视觉和交互系统

- 背景：主体使用浅灰蓝纯色，网格只保留在品牌头部的轻微纹理；
- 颜色：深蓝文字、Schale 蓝作为操作色、青色表示可执行/已选、粉色表示缺口或警示；
- 卡片：外层面板有边界，内层使用分隔线和浅底，不连续套多层阴影；
- 素材：学生头像、礼物图标、反应脸承担识别功能，Arona 只作为品牌装饰出现一次；
- 交互：统一使用“结果 → 操作 → 详情”的顺序，折叠标题带数量或状态摘要；
- 响应式：桌面保留窄侧栏；900px 以下减少品牌装饰；560px 以下使用抽屉/两行导航，所有工作区可发现，不允许横向裁切。

## 6. 保留的数据和纯函数边界

保留现有 localStorage、旧状态迁移、Arona JSON 导入/导出、三语 i18n、制造期望计算、规划摘要计算、库存预留/确认消耗和 Harness 安全边界。前端重构不得改写用户已有库存、规划或礼包购买事实。

建议以现有纯函数为数据层，新增一个页面级 view model：

```js
buildWorkbenchViewModel({ state, data, workbench, locale })
```

它只负责把已有计算结果整理成页面需要的摘要，不重新计算机制；渲染函数只接受 view model，不直接读取 localStorage。

## 7. 实施切片与验收

1. 壳层切片：左侧轨道、窄屏导航、品牌头部、语言切换；验收六个工作区都可达，默认进入规划。
2. 规划切片：目标栏、结果卡、固定操作区、明细折叠；验收缺口/天数和未实装口径正确。
3. 图鉴切片：目录收起、角色详情、反应脸和制造节点折叠；验收窄屏搜索后详情立即可见。
4. 库存与资源切片：摘要化折叠、图标化条目、空状态和导入导出；验收库存不被规划预览自动扣除。
5. 礼包与 Agent 切片：前三名比较、配置抽屉、建议审核；验收礼包不混入规划，Agent 不可绕过确认。
6. 回归切片：中文/英文/日文、1440/768/390 视口、现有单元测试、Harness 测试、真实浏览器截图和控制台检查。

每个切片完成后先跑对应测试并在真实浏览器检查，再进入下一切片；不一次性替换全部文件。

## 8. 非目标

- 本轮不重新调研或改写制造概率、礼物反应和国服资源数值；
- 不增加账号同步、后端数据库或云端库存；
- 不把礼包购买自动混入养成缺口；
- 不复制参考站点的完整页面、代码或受版权保护的整套素材。
