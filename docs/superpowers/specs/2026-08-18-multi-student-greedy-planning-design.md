# 多学生贪心规划设计

## 目标

解决加入第二个目标学生后，非主目标因没有被分配共享周期资源而直接显示“无法估算”的问题。规划顺序由主目标和其他目标共同定义，主目标优先使用可共享资源，其他目标在主目标之后继续估算。

## 规则

- 具体礼物按目标顺序贪心分配：先主目标，再按规划列表顺序分配其他目标。
- 当前目标已经满足，或库存中没有该目标喜欢的可用礼物时，才进入下一个目标。
- 主目标优先获得共享的日程、咖啡厅和周期礼物资源；其他目标的预计天数按主目标完成后的剩余资源继续计算。
- 预计天数是顺序规划中的累计天数，不再因为目标不是主目标而强制返回 `null`。
- 未实装/未知学生仍不获得日程和咖啡厅资源，只使用礼物相关资源。
- 没有任何可用礼物或免费资源时，仍显示“无法估算”，避免伪造速度。

## 实现边界

- 为礼物分配函数增加可选的目标优先级参数；未传入时保留原有全局分配行为。
- 规划摘要层根据目标顺序计算每张卡片的累计预计天数和剩余缺口。
- 不修改库存持久化、不修改礼包计划、不改变礼物盒金紫分类。

## 验收

- 单学生规划的现有结果保持不变。
- 双学生规划中，主目标和第二目标都能得到有限的预计天数；第二目标的时间不早于主目标完成时间。
- 多学生具体礼物不重复分配。
- 无免费资源的礼物-only 学生仍按已有规则显示“无法估算”。
- 现有 Node 测试、Harness 测试和浏览器规划页无控制台错误。
