# Schale 工作台视觉重构设计

## 目标

把 relationship dashboard 从“多张装饰横幅拼接的后台”重构为数据优先的 Schale 工作台。用户打开任意工作区后，第一眼应能看到当前状态、最重要的结果和下一步动作；图片只承担学生、礼物、资源的识别作用，不承担无语义的装饰。

## 设计原则

1. 一个产品只使用一套视觉语言：深蓝导航、冷白工作区、青色状态色、少量金色/粉色语义色。
2. 每个页面最多一个主视觉；规划页使用目标学生头像，图鉴页使用学生立绘，其余页面优先使用礼物/资源图标。
3. 删除外部站点 Logo 和拼贴横幅。数据来源放进折叠区或页脚，不参与首屏装饰。
4. 结果优先：缺口、预计天数、待填写项、比较结果和下一步操作高于说明文字。
5. 组件层级收敛：普通内容使用分隔线列表，只有页面主结果和可操作区使用面板；不再给每个小模块同时加圆角、边框、阴影和渐变。
6. 移动端从单列设计出发，所有统计项和筛选项必须在 390px 内直接可见或明确可展开，不依赖被裁切的横向内容。

## 工作区结构

### 养成规划

首屏为目标学生、规划周期、好感缺口、预计达成天数和“生成预留方案”。详细来源、礼物分配和计算口径放入折叠区；删除宣传型 Hero 和重复学生信息。

### 库存

顺序固定为导入/导出、当前持有概览、石头与礼物盒、礼物列表。导入 JSON 是主动作；礼物列表使用紧凑行，不再使用宣传横幅。

### 周期资源

先展示待填写/已确认的资源输入和本期合计，来源说明折叠。图片只使用资源图标，不展示 Kivo/Arona/SchaleDB Logo。

### 礼包性价比

顶部保留当前目标和三项关键比较结果；“当前快照”和“学生上线时”改为同一模块中的切换入口，礼包内容使用比较表/紧凑行，不重复堆叠两套长卡片。

### 学生与礼物图鉴

保留左侧学生目录和右侧详情的信息架构。学生身份、制造石期望、阶段节点和礼物列表按结果优先排列；三阶段统计在窄屏统一单列；礼物筛选换行或使用紧凑选择器。

### Agent 助手

首屏优先展示对话和当前规划摘要。未连接时只显示紧凑连接设置卡，不使用图片空状态；API Key 仍为密码输入，Agent 输出仍需本地审核后应用。

## 视觉令牌

- 背景：`#EEF4F8`
- 深蓝导航：`#102641`
- 主青色：`#4CC7D1`
- 主文字：`#172A42`
- 次文字：`#6D8092`
- 面板：`#FFFFFF`
- 边框：`#D6E2EA`
- 警告金：`#D19A35`
- 缺口粉：`#D96F90`
- 间距采用 8px 基准；普通圆角约 10px；阴影只保留一种低强度层级。

## 删除与重写范围

- 删除 `resource-art-strip`、`package-visual-anchors`、`agent-visual-anchors` 及规划/库存中的拼贴 Hero 子元素。
- 删除外站 Logo 的首屏展示和对应 CSS。
- 合并全局标题栏与工作区内部重复标题。
- 重写 `planner-view.js`、`inventory-view.js`、`resource-view.js`、`package-view.js`、`agent-view.js` 的首屏结构。
- 合并 `styles.css` 末尾覆盖层回基础组件规则，删除重复断点定义。

## 验收标准

- 1440px 六个工作区视觉语言一致，没有装饰性外站 Logo 或无语义拼贴横幅。
- 390px 六个工作区无横向溢出，统计项、筛选项和主操作可直接访问。
- 规划结果首屏优先显示缺口和预计天数；库存导入是库存页主动作；Agent 未连接状态紧凑。
- 中文、英文、日文不出现目标语言之外的装饰性文案。
- 页面无破图、控制台无错误，现有规划/库存/礼包/Agent 逻辑保持可用。
- 视觉改动拆成可回滚 Git 提交，并在每个切片后重新截图核对。
